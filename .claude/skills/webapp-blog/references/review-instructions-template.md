# Review 지침 파일 틀

`apps/{앱이름}/review-instructions.md`로 저장한다. Build 완료 보고의 "달라진 점"과 "우려"를 그대로 옮겨 우선 확인 항목으로 만든다. Build를 맡은 서브에이전트에게는 절대 주지 않는다.

---

~~~markdown
# Review 서브에이전트 지침 — {앱 표시 이름}

## 역할
Build 단계에서 만든 {앱 표시 이름}을 **독립적으로** 검증하고 결과를 `apps/{앱이름}/review.md`로 작성한다. 구현자(Build 서브에이전트)의 보고를 믿지 말고 직접 확인한다.

## 수정 가능 범위
- `apps/{앱이름}/review.md` 생성만 허용한다.
- 앱 코드({파일 목록})는 **수정하지 않는다.** 문제를 찾으면 고치지 말고 review.md에 적는다. 수정은 Build 서브에이전트가 맡는다.
- `apps/{앱이름}/` 밖의 파일, `spec.md`, 각종 `*-instructions.md`는 수정하지 않는다.
- git 명령은 실행하지 않는다.

## 기준 문서
- `apps/{앱이름}/spec.md` — "검증 기준 (Review 체크리스트)"를 빠짐없이 확인한다. 사용자 확정 사항은 spec 마지막 절.
- `CLAUDE.md` — 프로젝트 공통 규칙. 특히 **블로그 색상 팔레트(CSS 변수) 사용**과 **사용법 안내 문구 포함** 여부를 확인한다. 색은 `index.html`이 `../../css/style.css`를 불러오는지, 앱 `style.css`에 블로그 토큰 값이 복사돼 있지 않은지, 블로그 전역 스타일 때문에 앱 화면이 깨지지 않는지 본다.
- 참고: `apps/pixel-editor/review.md`, `apps/2048/review.md` — 이전 리뷰. 형식과 확인 깊이를 맞춘다.

## 확인 방법
- 서버: `http://localhost:8000/`이 이미 떠 있을 가능성이 높다. 응답이 없으면 프로젝트 루트(`C:\Users\HP\Desktop\my-blog`)에서 `node serve.mjs 8000`을 띄우고, 직접 띄운 서버만 끝나면 종료한다.
- 브라우저: 내장 브라우저 도구(`mcp__Claude_Browser__*`)로 확인한다. 모바일은 `resize_window`(mobile 프리셋), 테마는 `localStorage.theme` 설정 후 새로고침, 대비는 `getComputedStyle`로 실제 색을 읽어 계산한다. 끝나면 viewport를 desktop으로 되돌린다.
- 파일 다운로드가 있는 앱이면 실제로 내려받지 말 것(사용자 Downloads 폴더에 쌓인다). 클릭을 가로채거나 모듈 함수를 페이지에서 import해 결과물을 검사한다.
- {앱 고유 기능 확인 방법}
- 저장: 새로고침 후 복원, 손상된 저장 값, localStorage 차단 시 동작.
- 터치: 합성 touch PointerEvent로 확인, 조작 중 스크롤 없음.
- 코드 리뷰: 로직 버그, 엣지 케이스, 메모리 누수(리스너, object URL), 코딩 규칙(`innerHTML` 금지, 색은 CSS 변수로만, 순수 함수 분리, 작은따옴표·세미콜론·2칸).
- 확인 중 바꾼 `localStorage`(`apps.{앱이름}.*`, `theme`) 값은 끝나면 원래 상태로 되돌린다.
- 결과는 조금씩 review.md에 써 둔다 (중간에 끊겨도 진행 상황이 남도록).

## review.md 형식
```markdown
# {앱 표시 이름} — Review

## 요약
전체 판정(통과 / 수정 필요)과 한두 줄 설명

### 확인 환경·방법

## 체크리스트 결과
spec 검증 기준 항목별 표: | 항목 | 결과(✅ 통과 / ❌ 실패 / ⚠️ 미확인) | 근거(어떻게 확인했는지) |

## 발견한 문제
| 번호 | 심각도(높음/중간/낮음) | 위치(파일:줄) | 내용 | 재현 방법 | 수정 제안 |

## 참고 (문제는 아니지만 개선 여지)
```
- 추측으로 실패 판정하지 않는다. 직접 재현했거나 코드에서 확실히 확인한 것만 문제로 적는다.

## 완료 보고
전체 판정, 실패·미확인 항목 수, 심각도 높음/중간 문제 목록을 10줄 안팎으로 보고한다.
~~~
