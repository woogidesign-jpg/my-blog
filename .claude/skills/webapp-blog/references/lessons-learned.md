# 지난 앱에서 나온 교훈

Build 지침에는 "같은 실수 반복 금지"로, Review 지침에는 "꼭 확인할 것"으로 넣는다.

## 2048 Review에서
| 문제 | 원인 | 해결 |
|---|---|---|
| 마우스로 `새 게임`을 누르면 방향키가 안 먹고 페이지가 스크롤됨 | 포커스가 버튼에 남음 | 동작 뒤 보드로 포커스를 돌린다 (`boardEl.focus()`) |
| 일부 키 이벤트에서 TypeError | `event.key`가 undefined인 keydown | `(event.key || '')`로 방어 |

## 공통 원칙
- 드래그·스와이프 영역은 `touch-action: none`, 이동 키는 `preventDefault`로 페이지 스크롤을 막는다.
- 한글 입력 상태에서도 단축키가 동작하도록 `event.code`도 함께 본다.
- 비텍스트 요소(테두리, 포커스 표시, 격자선)는 3:1, 텍스트는 4.5:1 대비를 실측한다.
- localStorage는 항상 try/catch. 손상된 값이 있어도 오류 없이 기본 상태로 시작한다.
- 숨겨진 중복 버튼(반응형 때문에 두 개 둔 경우)은 탭 순서·스크린리더에서 빠지는지 확인한다.

## Review에서 꼭 확인할 것 (도구 한계로 미확인이 되기 쉬운 것)
- 실제 손가락 스와이프·드래그 → 합성 PointerEvent로 대신 확인하고 "미확인"으로 남길지 밝힌다.
- 실제 `prefers-reduced-motion` 설정 → CSS 규칙을 코드로 확인.
- 휴대폰 가로(667×375)에서 주요 영역이 화면을 넘는지.
- 데모 모드가 좁은 폭에서 깨지는지(캡처 전용이면 참고 항목).
