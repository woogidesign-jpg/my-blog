# Plan 서브에이전트 지침 — 2048

## 역할
2048 웹앱의 구현 계획을 세우고 `apps/2048/spec.md`로 저장한다. **코드는 작성하지 않는다.**

## 요청 내용 (사용자 원문 요약)
- 2048 게임: 방향키로 숫자 타일을 밀어서 같은 숫자를 합치는 퍼즐 게임
- 점수판 포함

## 수정 가능 범위
- `apps/2048/spec.md` 파일 생성만 허용한다.
- 그 외 파일은 읽기만 한다. 블로그 파일(`index.html`, `css/`, `js/`, `posts/` 등)은 수정하지 않는다.

## 참고할 것
- `CLAUDE.md`: 프로젝트 규칙 (웹앱은 `apps/{앱이름}/` 안에서 자체 완결, 외부 라이브러리 최소화, 모바일 지원)
- `css/style.css`: 블로그의 디자인 토큰(검은 배경 + 네온 색). 앱도 이 분위기에 맞추되, 앱 폴더 안에 자체 CSS로 둔다(블로그 CSS를 import하지 않음).
- 나중에 블로그 `index.html`에 카드(제목, 설명, 미리보기 이미지 또는 iframe)로 임베드된다는 점을 고려한다.

## spec.md에 담을 내용
1. **개요**: 앱 이름, 한 줄 설명, 블로그 카드용 설명 문구
2. **기능 목록**: 4×4 보드, 타일 이동·합치기 규칙(한 번 이동에 한 타일은 한 번만 합쳐짐), 새 타일 생성(2 또는 4 확률), 점수 계산, 최고 점수 저장(localStorage, try/catch), 승리(2048) / 게임 오버 판정, 새 게임 버튼, 계속하기 여부
3. **입력**: 방향키, WASD(선택), 모바일 스와이프(터치)
4. **화면 구성**: 헤더(제목, 현재 점수, 최고 점수), 보드, 안내 문구, 오버레이 메시지. 375px 모바일 레이아웃 기준.
5. **디자인**: 블로그 네온 테마 계승. 타일 값별 색을 어떻게 줄지(네온 3색 범위 안에서 밝기·글로우 단계 등), 애니메이션(이동·합치기·등장)과 `prefers-reduced-motion` 처리, 대비(WCAG AA)
6. **파일 구조**: `apps/2048/` 아래 파일 목록과 각 파일의 역할 (예: `index.html`, `style.css`, `game.js`(순수 로직), `ui.js`(DOM·입력), 테스트 페이지 여부, `preview.png` 등 카드용 미리보기)
7. **로직 설계**: 순수 함수로 분리할 핵심 함수 시그니처 (예: `move(board, direction) → { board, scoreGained, moved }`), DOM 없이 테스트 가능하게
8. **접근성**: 키보드 조작, 점수 변경 알림(`aria-live`), 버튼 크기 44px 이상
9. **검증 기준**: Review 단계에서 확인할 체크리스트 (동작, 모바일 가로 스크롤 없음, 콘솔 오류 없음 등)
10. **범위 밖**: 이번에 하지 않을 것 (예: 되돌리기, 보드 크기 변경 등)

## 작성 규칙
- 한국어로 작성한다.
- 간결하게, 구현자가 바로 따라 만들 수 있을 정도로 구체적으로 쓴다.
- 판단이 필요한 선택지가 있으면 추천안을 정하고, `## 사용자 확인 필요` 절에 따로 적는다.

## 완료 보고
작성을 마치면 spec.md의 핵심(파일 구조, 주요 결정, 확인 필요 사항)을 5~10줄로 요약해 보고한다.
