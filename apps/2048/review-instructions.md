# Review 서브에이전트 지침 — 2048

## 역할
Build 단계에서 만든 2048 웹앱을 **독립적으로** 검증하고 결과를 `apps/2048/review.md`로 작성한다. 구현자(Build 서브에이전트)의 보고를 믿지 말고 직접 확인한다.

## 수정 가능 범위
- `apps/2048/review.md` 생성만 허용한다.
- 앱 코드(`index.html`, `style.css`, `game.js`, `ui.js`, `storage.js`, `tests.html`, `preview.png`)는 **수정하지 않는다.** 문제를 찾으면 고치지 말고 review.md에 적는다. 수정은 Build 서브에이전트가 맡는다.
- `apps/2048/` 밖의 파일, `spec.md`, 각종 `*-instructions.md`는 수정하지 않는다.
- git 명령은 실행하지 않는다.

## 기준 문서
- `apps/2048/spec.md` — 특히 "9. 검증 기준 (Review 체크리스트)"를 빠짐없이 확인한다.
- `CLAUDE.md` — 프로젝트 공통 규칙.

## Build가 보고한 추가 사항 (계획서와 다른 점 — 문제가 없는지 같이 본다)
1. `ui.js`에 데모 모드(`?demo=1`): 미리 정한 보드, 최고 점수 저장 안 함, `<html class="is-demo">`로 2열 레이아웃.
2. 타일을 `.tile`(위치) + `.tile-inner`(크기 애니메이션·색) 두 겹으로 구성.
3. 2048 타일 맥동을 `::after` 글로우 레이어의 opacity로 구현.
4. `계속하기` 시 보드가 이미 막혀 있으면 곧바로 게임 오버 오버레이.

## Build가 확인하지 못했다고 한 것 (우선 확인)
- 승리·게임 오버 오버레이 실제 화면 동작 (콘솔에서 `fromValues` 등으로 보드를 주입해 확인)
- 모바일 스와이프 4방향, 스와이프 중 페이지 스크롤·새로고침 없음
- 375px 가로 스크롤 없음, 375×667에서 한 화면에 들어오는지
- 라이트 테마(`localStorage.theme = 'light'`) 대비
- `prefers-reduced-motion: reduce` 동작
- 오버레이 포커스 이동 (포커스 트랩 없음 — 문제인지 판단해서 적는다)

## 확인 방법
- 서버: `http://localhost:8000/`이 이미 떠 있을 가능성이 높다. 응답이 없으면 프로젝트 루트에서 `node serve.mjs 8000`을 띄우고, 끝나면 직접 띄운 서버만 종료한다.
- 브라우저: 사용할 수 있으면 내장 브라우저 도구(`mcp__Claude_Browser__*`)로 페이지를 열어 확인한다. 모바일은 `resize_window`(mobile 프리셋), 색 테마는 `localStorage` 설정 후 새로고침, 대비는 `getComputedStyle`로 실제 색을 읽어 계산한다. 끝나면 viewport를 desktop으로 되돌린다.
- 브라우저 도구를 쓸 수 없으면 Edge/Chrome 헤드리스(`--dump-dom`, `--screenshot`) 등으로 가능한 만큼 확인하고, 확인하지 못한 항목은 review.md에 "미확인"으로 표시한다.
- 코드 리뷰: 로직 버그, 엣지 케이스(빠른 연속 입력, 오버레이 중 입력, 애니메이션 중 새 게임), 메모리 누수(제거되지 않는 DOM·리스너), 코딩 규칙(`innerHTML` 금지, 색상값 직접 사용 금지, `game.js` 순수성, 작은따옴표·세미콜론·2칸).

## review.md 형식
```markdown
# 2048 — Review

## 요약
전체 판정(통과 / 수정 필요)과 한두 줄 설명

## 체크리스트 결과
spec.md 9절 항목별로 ✅ 통과 / ❌ 실패 / ⚠️ 미확인 + 근거(어떻게 확인했는지)

## 발견한 문제
| 번호 | 심각도(높음/중간/낮음) | 위치(파일:줄) | 내용 | 재현 방법 | 수정 제안 |

## 참고 (문제는 아니지만 개선 여지)
```
- 추측으로 실패 판정하지 않는다. 직접 재현했거나 코드에서 확실히 확인한 것만 문제로 적는다.
