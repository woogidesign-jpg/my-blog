# SLATE 쇼핑몰 — Review

## 요약
**판정: 수정 필요 (경미)** — spec 12절 33개 항목 중 실패 1개(누름 영역 44px, 낮음), 부분 확인/미확인 4개(실제 손가락 스와이프, 실제 `prefers-reduced-motion`, 실제 클립보드 복사, git 기준 외부 파일 변경 — 모두 도구 한계). 홈 ↔ 상세 왕복(스크롤·필터·더보기 복원, 상세 주소로 바로 열고 ←, 없는 id), 찜 동기화, 사이즈 경고, 수량 끝값, 장바구니 합치기·저장, 손상 값, localStorage 차단, 데모 모드, 360~1280px 레이아웃, 대비를 직접 재현해 확인했습니다. 심각도 높음·중간 문제는 없습니다. 낮음 2건: `전체 →` 버튼 폭 42.6px(44 미만), 카드 상품명 링크 높이 21px(같은 곳으로 가는 이미지 링크가 있어 실사용 영향은 작음).

### 확인 환경·방법
- 서버: 이미 떠 있던 `http://localhost:8000/` 사용(직접 띄운 서버 없음).
- 브라우저: 내장 브라우저(Chromium). 390×844를 기본으로 360×740, 375×812, 667×375(가로), 1280×800에서 확인. 끝난 뒤 viewport를 desktop으로 되돌렸습니다.
- 입력: 대부분 `element.click()`·`location.hash`·`history.back/forward`로 보냈고, 키보드 흐름(Enter·Tab·Space)과 공유 버튼은 실제 키·실제 클릭으로 확인했습니다. 스와이프는 합성 `PointerEvent`(`pointerType:'touch'`)로 보냈습니다.
- **부드러운 스크롤**: 확인하는 동안 브라우저 창이 숨겨져 있어 `behavior:'smooth'` 스크롤이 전혀 진행되지 않았습니다(`window.scrollTo({behavior:'smooth'})`도 0에서 멈춤 — 환경 문제). 그래서 `Element.prototype.scrollIntoView`를 감싸 호출 인자(`{behavior:'smooth', block:'start'}`)를 기록하고 `behavior:'auto'`로 바꿔 실행해 도착 위치를 측정했습니다.
- localStorage 차단: `Storage.prototype.getItem/setItem/removeItem`이 `SecurityError`를 던지게 하는 스크립트를 `<head>` 맨 앞에 넣은 index.html 사본을 같은 origin `srcdoc` iframe(+`<base>`)에 띄워 확인(파일은 수정하지 않음).
- 데모 모드: 1200×630 iframe에 `?demo=1`을 띄워 확인.
- 대비: `getComputedStyle`로 실제 색을 읽고 반투명 색은 아래 배경과 섞어 WCAG 공식으로 계산.
- 시작 전 localStorage: `apps.slate-shop.wish`, `apps.slate-shop.cart`, `theme` 모두 없음 → 끝난 뒤 세 키를 지워 원래 상태로 되돌림.

## 참고 (문제는 아니지만 개선 여지)
- **preview.png 홈 프레임**: 맨 위에서 카테고리 라벨(아우터·상의…) 아랫부분이 헤더 바로 밑에 반쯤 잘린 채 한 줄 보임(ui.js:254–255에서 `new-section.offsetTop − headerH − 8`로 스크롤). 신상품 제목 위 여백(48px) 안에 잘린 글자가 걸린 것이라 카드 썸네일 크기에서는 "깨진 글자"처럼 보여 약간 어색함. `− 8`을 `+ 40` 정도로 바꿔 라벨이 완전히 헤더 아래로 숨게 하거나, 반대로 카테고리 라벨 줄 전체가 보이도록 더 위에서 시작하면 깔끔함. 기능 문제는 아님.
- **`cameFromHome`이 상세 → 다른 상세 이동 때 유지됨**(ui.js:207–211): 홈 → 1번 → 주소창에서 `#/product/2`로 바꾼 뒤 ← 를 누르면 `history.back()`이라 홈이 아니라 1번으로 감. 앱 안에는 상세 → 상세 링크가 없어 주소를 직접 고칠 때만 생기므로 문제로 보지 않음(코드 판단). 원하면 `prev.name !== 'home'`일 때 `cameFromHome = false`로.
- **경고 문구 타이머**(product.js:113–115): `setSizeError(true)` 직후 30ms 안에 없는 상품 주소로 바뀌면 `state.product`가 `null`이라 `state.product.sizeError`에서 TypeError가 날 수 있음. 사람이 만들기 어려운 타이밍이라 재현하지 않음(코드로만 확인). `if (state.product && state.product.sizeError)`로 막으면 안전.
- **밝은 스와치 테두리**: 화이트(`#F5F5F2`)·아이보리 스와치의 `--sl-swatch-edge` 테두리가 흰 배경 대비 약 1.5~2.1:1. 바로 아래 색 이름 글자(`화이트`)가 있어 식별에 문제는 없음. 테두리를 `rgba(0,0,0,.3)` 정도로 올리면 더 또렷함.
- **비활성 수량 버튼**(`--sl-divider` 글자 3.54:1): WCAG 예외라 그대로 둬도 됨.
- **이미지 위 이전/다음 버튼 바탕**(`--sl-scrim-light`)은 이미지 자리(`#EDEDED`)와 1.14:1로 거의 구분되지 않음. 아이콘(18:1)으로 식별되므로 문제는 아니며, 실제 사진이 들어가면 바탕이 제 역할을 함.
- **스와이프 영역**: 이미지 상자(`#pd-image`)에만 리스너가 있어 카운터·이전/다음 버튼 위에서 시작한 스와이프는 무시됨. 영역이 작아 실사용 영향은 작음.
- **카테고리 `상의`/짧은 목록**: 결과가 2개면 문서 끝에 막혀 `신상품` 제목이 화면 가운데쯤(top 345)에 멈춤. 의도된 스크롤 대상은 보이므로 문제 아님.
- 정리: 확인용으로 바꾼 localStorage(`apps.slate-shop.wish`, `apps.slate-shop.cart`, `theme`)는 원래 세 키 모두 없었으므로 지워서 되돌렸습니다. viewport는 desktop으로 되돌렸습니다. 서버는 원래 떠 있던 것을 썼습니다. 확인용 iframe은 모두 제거했습니다.
