## spec.md에서 특히 결정할 것
1. **개요**: 앱 이름, 한 줄 설명, 블로그 카드 문구·분류·태그
2. **화면 연결 방식**: 한 페이지 안 해시 라우팅(`#/`, `#/product/{id}`) vs HTML 두 장. 추천안과 이유. 뒤로가기(브라우저 back) 동작, 스크롤 위치, 상품 8개 데이터 중 상세가 어느 상품을 보여 주는지(디자인은 코트 하나만 있음 → 상품 데이터에 가격·색상·사이즈를 넣어 상세를 상품별로 채울지).
3. **핵심 기능**: 필터 칩, 찜(홈과 상세가 공유), 장바구니 개수(헤더 표시), 색/사이즈/수량 선택, 사이즈 미선택 경고, 이미지 이전/다음, 사이즈 가이드 앵커. 디자인의 죽은 링크(메뉴, 검색, 탭 바 등)를 어떻게 다룰지. 꼭 필요한 것과 범위 밖을 구분.
4. **사용법 안내**: 디자인에 없는 요소이므로 어디에 어떤 문구로 넣을지(예: 상단 띠 배너 자리, 접이식 안내).
5. **색 — 가장 중요한 충돌**: 디자인은 흰 배경 + 검정 모노톤 쇼핑몰이고, CLAUDE.md는 "모든 웹앱은 블로그 색상 팔레트(네온)를 따른다"고 한다. 선택지를 만들고 추천안을 정해 `## 사용자 확인 필요` 1번에 올린다. 예: (A) 블로그 `style.css`를 불러와 토큰으로 매핑(라이트 테마에서 디자인과 가깝게, 다크에서는 네온), (B) 디자인 그대로 흑백 고정, (C) 기타. 어느 경우든 `<link>` 순서, 덮어쓸 블로그 전역 규칙(body 배경 격자, 제목 글꼴·글로우 등), 앱 토큰 정의를 적는다.
6. **작업 보존**: localStorage(키 접두사 `apps.slate-shop.`)로 찜·장바구니를 저장할지, try/catch, 손상된 값 처리.
7. **입력**: 터치·마우스·키보드, 포커스 표시, 이미지 스와이프 추가 여부.
8. **화면 구성**: 390px 고정 폭 컬럼(`max-width`), 하단 탭 바·구매 바를 `position: fixed/sticky`로 할지, safe-area.
9. **디자인 세부**: 디자인의 폰트 크기·간격·반경·테두리를 그대로 옮길 값 목록, 아이콘 SVG 재사용, 대비 AA, 터치 대상 44px, `prefers-reduced-motion`.
10. **파일 구조**: `apps/slate-shop/` 아래 파일 목록과 역할 (예: `index.html`, `style.css`, `data.js`, `shop.js` 순수 로직, `storage.js`, `ui.js`, `tests.html`, `preview.png`).
11. **로직 설계**: 순수 함수 시그니처(필터, 찜 토글, 장바구니 추가, 수량 범위, 가격 포맷, 라우트 파싱 등), `tests.html` 최소 케이스.
12. **검증 기준**: Review 체크리스트(어떻게 확인할지까지, 홈↔상세 왕복 포함).
13. **범위 밖**: 이번에 하지 않을 것(결제, 실제 검색, 장바구니 페이지 등).

## 작성 규칙
- 한국어로 작성한다.
- 간결하게, 구현자가 바로 따라 만들 수 있을 정도로 구체적으로 쓴다.
- 판단이 필요한 선택지가 있으면 추천안을 정하고, 마지막 `## 사용자 확인 필요` 절에 따로 적는다 (5개 안팎).
- `CLAUDE.md` 규칙과 다르게 가는 결정은 혼자 정하지 말고 반드시 `## 사용자 확인 필요`에 올린다.
