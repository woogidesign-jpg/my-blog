# 픽셀 에디터 — Review

## 요약
**판정: 수정 필요 (경미)** — spec 13절 29개 항목 중 실패 0개, 부분 확인/미확인 3개(실제 손가락 제스처, 실제 reduced-motion 미디어 쿼리, git 기준 외부 파일 변경 — 모두 도구 한계). 그리기·히스토리·자동 저장·PNG 픽셀 값·레이아웃·키보드 조작·대비는 직접 재현해 통과했습니다. 다만 **마우스를 누른 채 Ctrl+Z/Ctrl+Y를 누르면 화면과 저장 데이터가 어긋나는 문제(중간)** 를 재현했고, Build가 우려한 **다크 테마 격자선이 체커보드 위에서 사실상 안 보이는 문제(중간)** 를 실측으로 확인했습니다. 둘 다 몇 줄이면 고칠 수 있습니다.

### 확인 환경·방법
- 서버: 이미 떠 있던 `http://localhost:8000/` 사용(직접 띄운 서버 없음).
- 브라우저: 내장 브라우저(Chromium). 기본 폭 736×646(640~1023 배치), `mobile` 프리셋 375×812, 667×375(휴대폰 가로), 1280×800에서 확인했고 끝난 뒤 viewport를 desktop으로 되돌렸습니다.
- 실제 입력: 마우스 드래그(`left_click_drag`), Tab/Shift+Tab, 방향키, Space, Enter, Ctrl+Z, Ctrl+Shift+Z는 브라우저 도구로 보냈습니다. 빠른 대각선, 터치, 두 번째 포인터, pointercancel, 한글 IME(`key:'ㅠ', code:'KeyB'` 등)는 합성 `PointerEvent`/`KeyboardEvent`로 보냈습니다.
- localStorage 차단: `Storage.prototype.getItem/setItem/removeItem`이 `SecurityError`를 던지게 하는 스크립트를 `<head>` 맨 앞에 넣은 index.html 사본을 같은 origin의 `srcdoc` iframe에 띄워 확인했습니다(파일은 수정하지 않음).
- PNG: 실제 파일은 내려받지 않았습니다. `HTMLAnchorElement.prototype.click`과 `URL.createObjectURL`을 가로채 실제 `PNG 저장` 버튼이 만든 blob을 받아, `createImageBitmap` → canvas → `getImageData`로 모든 픽셀을 검사했습니다.
- 대비는 `getComputedStyle`로 실제 토큰 값을 읽어 WCAG 공식으로 계산했습니다.
- 참고: 확인하는 동안 브라우저 창이 숨겨져 있어 `requestAnimationFrame`이 느리게 돌았습니다. 상태 줄(`announce`가 rAF 안에서 글자를 넣음)은 1~2초 기다리거나 rAF를 `setTimeout`으로 바꾼 뒤 읽었습니다. 앱 문제는 아닙니다.

### Build가 보고한 계획서와 다른 점
1. **PNG 저장 버튼 두 개**: 문제 없음. 숨겨진 쪽은 `display: none`이라 Tab 순서에서 빠지고(736px Tab 순회에 `save-side` 없음) 접근성 트리에도 나타나지 않음. 1024px 이상에서는 반대로 `save-top`이 빠짐.
2. **640~1023px 단순화**: 문제 없음. 견본 53px로 44px 이상, 가로 스크롤 없음. spec의 "도구·현재 색·토글 한 줄" 대신 두 줄이지만 기능·크기에 지장 없음.
3. **`toRgbaPixels` → `putImageData`**: 문제 없음. 위 PNG 검사에서 모든 픽셀 일치.
4. **`.is-keyboard` 클래스**: 문제 없음. Tab으로 들어오면 커서·외곽선 표시, 보드를 마우스로 누르면 클래스 제거·커서 숨김, 방향키를 누르면 다시 표시.
5. **데모 모드**: 문제 없음. localStorage를 읽지도 쓰지도 않음(위 표). preview.png는 1200×630.

## 참고 (문제는 아니지만 개선 여지)
- **이전 앱(2048) 유형 확인**: ① 도구·견본·지우기 버튼을 마우스로 누른 뒤에도 포커스가 버튼에 남지만 전역 단축키(`B E F I G`, Ctrl+Z)는 그대로 동작함(버튼은 입력 대상으로 보지 않음). 방향키는 spec상 보드에 포커스가 있을 때만 쓰므로, 버튼에 포커스가 있을 때 방향키가 페이지를 스크롤하는 것은 정상 동작으로 판단. ② 보드에 포커스를 주는 곳은 `pointerdown`의 `board.focus({ preventScroll: true })` 한 곳뿐이고, 667×375에서 첫 로드와 보드 클릭 후 모두 `scrollY 0` 유지. ③ `key`가 없는 keydown도 `(event.key || '')`로 처리되어 오류 없음.
- **직접 선택 칸(투명 color input)**: 접근 가능한 이름은 `<label for>`로 `직접 선택`이 붙고(`input.labels` 확인), `tabIndex 0`이라 Tab으로 닿으며, 네이티브 color input이라 Enter/Space로 열림. input이 라벨 전체(51.7×111px)를 덮어 클릭도 확실함. 포커스 표시는 `.custom:focus-within` 외곽선이라 **마우스로 눌렀을 때도 외곽선이 생김** → `.custom:has(.custom-input:focus-visible)`로 바꾸면 키보드일 때만 보임.
- **키보드로 칠했을 때 알림 없음**: Space/Enter로 칠하거나 지워도 상태 줄은 직전 커서 알림(`x 10, y 12: 빈 칸`)을 그대로 보여 줘 내용이 낡은 상태가 됨. spec이 요구하지는 않지만, 적용 뒤 `announceCursor()`를 한 번 부르면 스크린리더 사용자가 결과를 알 수 있음.
- **휴대폰 가로(667×375)**: 640px 배치라 보드가 512px로 커져 화면 높이(375px)를 넘고 도구가 첫 화면 밖(top 630)에 있음. spec은 375×667 세로만 요구하므로 문제로 보지 않음. 원하면 `.board-wrap { width: min(100%, var(--board-max), 100svh - 여유) }` 같은 높이 제한을 고려.
- **데모 모드 레이아웃**: `.is-demo .app`이 540px+420px+56px 고정이라 폭 약 1056px보다 좁으면 가로로 넘침(736px에서 `scrollWidth 1056`). 1200×630 캡처 전용이라 문제로 보지 않음.
- **상태 줄과 rAF**: `announce()`가 `requestAnimationFrame` 안에서 글자를 넣어서, 탭이 백그라운드면 알림이 늦게 들어감. 실사용에서는 문제 없음. `setTimeout(…, 50)`을 써도 같은 효과(재낭독)를 얻을 수 있음.
- `toBlob`이 `null`을 줄 때 `PNG를 만들지 못했습니다`로 가는 경로는 코드로만 확인(export.js:53–56 → ui.js:257).
- 정리: 확인용으로 바꾼 localStorage(`apps.pixel-editor.drawing`, `apps.pixel-editor.settings`, `theme`)는 원래 세 키 모두 없었으므로 끝난 뒤 지워 원래 상태로 되돌렸습니다. viewport는 desktop으로 되돌렸습니다. 서버는 원래 떠 있던 것을 썼습니다.

### 참고
- 가드는 `applyToolAt` 안에 있어 획 도중 방향키 커서 이동과 `B E F I G`(도구·격자선)는 그대로 동작합니다. 히스토리를 건드리지 않는 동작이라 문제없습니다.
- (기존부터 있던 매우 드문 경우) `setPointerCapture`가 실패한 상태에서 보드 밖에서 버튼을 떼면 `activePointerId`가 남아, 다음에 보드를 한 번 누를 때까지 되돌리기·키보드 적용이 막힙니다. 그 클릭의 `pointerup`으로 바로 풀리므로 문제로 적지 않았습니다(코드로만 판단, 재현하지 않음). 필요하면 `window`의 `pointerup`에서도 `finishStroke()`를 부르면 완전히 막을 수 있습니다.
- 정리: 확인용 localStorage(`apps.pixel-editor.drawing`, `apps.pixel-editor.settings`, `theme`)는 원래 세 키 모두 없었으므로 지워서 되돌렸습니다(`apps.2048.best`는 건드리지 않음). viewport는 desktop으로 되돌렸습니다. 서버는 원래 떠 있던 것을 썼습니다.
