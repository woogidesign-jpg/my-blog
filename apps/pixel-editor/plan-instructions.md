# Plan 서브에이전트 지침 — 픽셀 아트 에디터

## 역할
픽셀 아트 에디터 웹앱의 구현 계획을 세우고 `apps/pixel-editor/spec.md`로 저장한다. **코드는 작성하지 않는다.**

## 요청 내용 (사용자 원문 요약)
- 16×16 격자에 도트를 찍어서 그림을 그리는 픽셀 아트 에디터
- 완성하면 PNG로 저장할 수 있어야 함
- 색상 팔레트 포함

## 수정 가능 범위
- `apps/pixel-editor/spec.md` 파일 생성만 허용한다.
- 그 외 파일은 읽기만 한다. 블로그 파일(`index.html`, `css/`, `js/`, `posts/` 등)과 `apps/2048/`은 수정하지 않는다.
- git 명령은 실행하지 않는다.

## 참고할 것
- `CLAUDE.md`: 프로젝트 규칙 (웹앱은 `apps/{앱이름}/` 안에서 자체 완결, 외부 라이브러리 최소화(CDN 허용), 모바일 지원)
- `apps/2048/spec.md`: 이전에 승인된 계획서. **형식과 상세 수준을 이것에 맞춘다.** 블로그 토큰을 앱 CSS로 복사하는 방식, 테마(`localStorage.theme`)를 따르는 방식, 데모 모드로 `preview.png`를 만드는 방식 등 이미 정한 관례를 재사용한다.
- `apps/2048/`의 구현 파일: 구조(순수 로직 / UI 분리, `tests.html`) 참고용.
- `css/style.css`: 블로그 디자인 토큰(검은 배경 + 네온 색).
- 나중에 블로그 `index.html`의 `ls apps/` 섹션에 카드(미리보기 이미지 + 링크)로 추가된다.

## spec.md에서 특히 결정할 것
1. **개요**: 앱 이름, 한 줄 설명, 블로그 카드 문구와 태그
2. **그리기 기능**: 연필(클릭·드래그로 연속 칠하기), 지우개, 채우기(flood fill) 여부, 스포이트 여부, 되돌리기/다시하기 여부, 전체 지우기(확인 여부), 격자선 표시 토글 여부. 꼭 필요한 것과 범위 밖을 구분한다.
3. **팔레트**: 기본 색 개수와 구성(예: 16색 고정 팔레트), 사용자 지정 색(`<input type="color">`) 여부, 현재 색 표시. 주의: 블로그 CSS 규칙("색은 토큰으로만")은 **UI 크롬**에 적용되고, 그림 팔레트 색은 사용자 데이터이므로 예외로 다룬다는 점을 명시하고 그 처리 방식을 정한다.
4. **투명 배경**: 빈 칸은 투명으로 둘지, 화면에서 체커보드로 표시할지, PNG 저장 시 투명 유지할지.
5. **PNG 저장**: canvas로 생성, 저장 배율(16×16 원본은 너무 작으니 예: 16px/도트 → 256×256 또는 배율 선택), `image-rendering: pixelated` 등 뭉개짐 방지, 파일 이름 규칙, 다운로드 방식(`<a download>` + `toBlob`).
6. **작업 보존**: 새로고침 시 그림을 `localStorage`에 자동 저장할지 (키 접두사 `apps.pixel-editor.`, try/catch).
7. **입력**: 마우스, 터치(Pointer Events로 드래그 칠하기, 그리는 중 스크롤 방지), 키보드 단축키(선택), 키보드만으로 칸 이동·칠하기가 가능한지(접근성).
8. **화면 구성**: 375px 모바일 기준 레이아웃(격자는 화면 폭에 맞춘 정사각형, 각 칸 최소 크기와 터치 정확도 고려), 640px/1024px에서 도구·팔레트 배치.
9. **디자인**: 블로그 네온 테마 계승, 선택된 도구·색 표시, `prefers-reduced-motion`, 대비(WCAG AA), 터치 대상 44px 이상(격자 칸은 예외일 수 있음 — 처리 방식을 정한다).
10. **파일 구조**: `apps/pixel-editor/` 아래 파일 목록과 역할 (예: `index.html`, `style.css`, `editor.js`(순수 로직: 격자 데이터, 칠하기, flood fill, 히스토리), `ui.js`, `export.js`(PNG), `storage.js`, `tests.html`, `preview.png`)
11. **로직 설계**: 순수 함수 시그니처 (예: `setPixel(grid, x, y, color) → grid`, `floodFill(grid, x, y, color) → grid`), 격자 데이터 표현(색 문자열 배열 / 팔레트 인덱스 등), DOM 없이 테스트 가능하게
12. **검증 기준**: Review 단계 체크리스트 (PNG 저장 결과 확인 방법 포함: 픽셀 값이 그린 것과 일치하는지)
13. **범위 밖**: 이번에 하지 않을 것 (예: 격자 크기 변경, 레이어, 애니메이션 프레임, PNG 불러오기 등)

## 작성 규칙
- 한국어로 작성한다.
- 간결하게, 구현자가 바로 따라 만들 수 있을 정도로 구체적으로 쓴다.
- 판단이 필요한 선택지가 있으면 추천안을 정하고, 마지막 `## 사용자 확인 필요` 절에 따로 적는다 (5개 안팎).
