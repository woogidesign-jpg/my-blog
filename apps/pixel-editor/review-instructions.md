# Review 서브에이전트 지침 — 픽셀 아트 에디터

## 역할
Build 단계에서 만든 픽셀 에디터를 **독립적으로** 검증하고 결과를 `apps/pixel-editor/review.md`로 작성한다. 구현자(Build 서브에이전트)의 보고를 믿지 말고 직접 확인한다.

## 수정 가능 범위
- `apps/pixel-editor/review.md` 생성만 허용한다.
- 앱 코드(`index.html`, `style.css`, `editor.js`, `export.js`, `storage.js`, `ui.js`, `tests.html`, `preview.png`)는 **수정하지 않는다.** 문제를 찾으면 고치지 말고 review.md에 적는다. 수정은 Build 서브에이전트가 맡는다.
- `apps/pixel-editor/` 밖의 파일, `spec.md`, 각종 `*-instructions.md`는 수정하지 않는다.
- git 명령은 실행하지 않는다.

## 기준 문서
- `apps/pixel-editor/spec.md` — 특히 "13. 검증 기준 (Review 체크리스트)"를 빠짐없이 확인한다. 사용자 확정 사항 6가지는 spec 마지막 절(모두 추천안).
- `CLAUDE.md` — 프로젝트 공통 규칙.
- 참고: `apps/2048/review.md` — 같은 프로젝트의 이전 리뷰. 형식과 확인 깊이를 맞춘다.

## Build가 보고한 계획서와 다른 점 (문제가 없는지 같이 본다)
1. PNG 저장 버튼이 두 개(`#save-top`은 1024px 미만, `#save-side`는 1024px 이상에서만 표시). 숨겨진 쪽이 탭 순서·스크린리더에 잡히지 않는지 확인.
2. 640~1023px 배치 단순화(팔레트 9열 격자, 도구 줄 두 줄).
3. PNG를 `toRgbaPixels` → `putImageData`로 생성.
4. 키보드 커서 표시를 `:focus-visible` 대신 `.is-keyboard` 클래스(마지막 입력 방식)로 판단.
5. 데모 모드 `?demo=1` (localStorage 읽기·쓰기 없음).

## Build가 직접 지적한 우려 (우선 확인)
- 다크 테마 격자선(`--line` #1c3a2b)이 체커보드(#2a2a2a/#383838) 위에서 거의 안 보임 → 실측하고, 문제라면 어떤 토큰 값이 적절한지 제안.
- 빈 칸 호버 테두리(청록)와 키보드 커서의 대비 실측 (비텍스트 요소 3:1 기준).
- 직접 선택 칸: 투명 color input이 라벨을 덮는 구조 → 포커스 표시, 접근 가능한 이름, 키보드로 열 수 있는지.

## 이전 앱(2048) 리뷰에서 나온 유형 (같은 문제가 없는지 확인)
- 버튼을 마우스로 누른 뒤 포커스가 버튼에 남아 단축키·방향키가 막히거나 페이지가 스크롤되는지.
- 프로그램으로 포커스를 옮길 때 세로가 짧은 화면(예: 667×375)에서 페이지가 튀는지.
- `event.key`가 없는 keydown에서 오류가 나는지.

## 확인 방법
- 서버: `http://localhost:8000/`이 이미 떠 있을 가능성이 높다. 응답이 없으면 프로젝트 루트(`C:\Users\HP\Desktop\my-blog`)에서 `node serve.mjs 8000`을 띄우고, 직접 띄운 서버만 끝나면 종료한다.
- 브라우저: 내장 브라우저 도구(`mcp__Claude_Browser__*`)로 확인한다. 모바일은 `resize_window`(mobile 프리셋), 테마는 `localStorage.theme` 설정 후 새로고침, 대비는 `getComputedStyle`로 실제 색을 읽어 계산한다. 끝나면 viewport를 desktop으로 되돌린다.
- **PNG 검증**: 실제 파일을 내려받지 말 것(사용자 Downloads 폴더에 파일이 쌓인다). 다운로드 링크 클릭을 가로채거나, `export.js` 함수를 페이지에서 import해 canvas/blob을 만든 뒤 `getImageData`로 각 칸 중앙 RGBA, 빈 칸 알파 0, 칸 경계 흐림 없음, 배율별 크기를 확인한다.
- 그리기 검증: 연필 드래그(빠른 대각선 보간), 지우개, 채우기(4방향, 같은 색일 때 무동작), 스포이트(연필 복귀, 빈 칸 안내, 팔레트 밖 색은 직접 선택 칸으로), 되돌리기/다시하기(획 단위, 100단계 상한), 전체 지우기(빈 그림일 때 확인창 없음, 되돌리기 복구), 격자선 토글, 단축키(B/E/F/I/G, Ctrl+Z/Shift+Z/Y, 한글 입력 상태의 `event.code`).
- 자동 저장: 새로고침 후 복원, 손상된 저장 값(형식 오류)이 들어 있을 때 오류 없이 빈 그림으로 시작, localStorage 차단 시 동작.
- 터치: 합성 touch PointerEvent로 드래그 칠하기, 두 번째 포인터 무시, 그리는 중 스크롤 없음.
- 코드 리뷰: 로직 버그, 엣지 케이스, 메모리 누수(object URL 해제, 리스너), 코딩 규칙(`innerHTML` 금지, UI 색상값 직접 사용 금지 / 그림 색 예외 처리, 순수 함수 분리, 작은따옴표·세미콜론·2칸).
- 확인 중 바꾼 `localStorage`(`apps.pixel-editor.*`, `theme`) 값은 끝나면 원래 상태로 되돌린다.

## review.md 형식
`apps/2048/review.md`와 같은 구성으로 쓴다.
```markdown
# 픽셀 에디터 — Review

## 요약
전체 판정(통과 / 수정 필요)과 한두 줄 설명

## 체크리스트 결과
spec.md 13절 항목별로 ✅ 통과 / ❌ 실패 / ⚠️ 미확인 + 근거(어떻게 확인했는지)

## 발견한 문제
| 번호 | 심각도(높음/중간/낮음) | 위치(파일:줄) | 내용 | 재현 방법 | 수정 제안 |

## 참고 (문제는 아니지만 개선 여지)
```
- 추측으로 실패 판정하지 않는다. 직접 재현했거나 코드에서 확실히 확인한 것만 문제로 적는다.
