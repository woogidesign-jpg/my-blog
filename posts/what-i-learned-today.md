오늘은 클로드 코드와 함께 이 블로그를 처음부터 만들어 봤습니다. 프레임워크 없이 HTML, CSS, JavaScript만 썼더니 세 가지가 각각 무슨 일을 하는지 또렷하게 보였습니다.

## 한 줄 요약

| 언어 | 역할 | 비유 |
|:-----|:-----|:-----|
| HTML | 내용과 구조 | 집의 뼈대 |
| CSS | 모양과 배치 | 인테리어 |
| JavaScript | 동작과 데이터 처리 | 전기와 배선 |

## HTML: 무엇이 있는지

HTML은 페이지에 **무엇이 있는지**를 정합니다. 이 블로그에서는 헤더, 본문, 푸터 같은 큰 틀을 HTML로 잡았습니다.

- `<header>`, `<main>`, `<footer>`처럼 뜻이 담긴 태그를 쓰면 구조가 읽기 쉬워집니다.
- `<meta name="viewport">` 한 줄이 있어야 모바일에서 화면이 제대로 맞춰집니다.
- 글 내용은 HTML에 직접 쓰지 않고, 빈 자리만 만들어 둔 뒤 JavaScript가 채웁니다.

## CSS: 어떻게 보이는지

CSS는 그 내용이 **어떻게 보이는지**를 정합니다.

- 색을 `--bg`, `--text` 같은 **CSS 변수**로 모아 두니, 다크 모드는 변수 값만 바꾸면 끝났습니다.
- `max-width: 68ch`로 한 줄 길이를 제한하면 글이 훨씬 읽기 편해집니다.
- 좁은 화면을 기준으로 먼저 만들고, `@media (min-width: 640px)`로 넓은 화면을 덧붙이는 **모바일 우선** 방식을 배웠습니다.
- 한글은 `word-break: keep-all`을 주면 단어 중간에서 줄이 끊기지 않습니다.

방금도 글 제목 색을 파란색으로 바꿨는데, `color: var(--accent);` 한 줄이면 충분했습니다. 라이트·다크 모드에 맞는 파란색이 알아서 적용됩니다.

## JavaScript: 무엇을 하는지

JavaScript는 페이지가 **무엇을 하는지**를 정합니다. 이 블로그에서 가장 많은 일을 하는 부분입니다.

1. `fetch`로 `posts/` 폴더의 마크다운 파일을 불러옵니다.
2. 글 맨 위의 제목, 날짜, 태그(front matter)를 읽어 냅니다.
3. 마크다운을 HTML로 바꿔 화면에 넣습니다.
4. 테마 버튼을 누르면 다크 모드로 바꾸고, 선택을 `localStorage`에 저장합니다.

```javascript
const response = await fetch('posts/hello-world.md');
const text = await response.text();
content.innerHTML = parseMarkdown(text);
```

> 마크다운 안의 HTML을 그대로 넣으면 위험할 수 있어서, 변환하기 전에 `<`, `>` 같은 문자를 먼저 바꿔 둡니다.

## 그 밖에 알게 된 것

- `fetch`는 파일을 더블클릭해서 연 페이지(`file://`)에서는 동작하지 않습니다. 그래서 `node serve.mjs`로 로컬 서버를 켜고 봐야 합니다.
- 브라우저는 폴더 안의 파일 목록을 직접 읽을 수 없습니다. 새 글을 쓰면 `posts/index.json`에 파일 이름을 추가해야 하는데, 이 글도 그렇게 추가했습니다.

세 가지가 각자 맡은 일만 하도록 나눠 두니, 고칠 곳을 찾기도 쉬웠습니다. 다음에는 태그별로 글을 모아 보는 기능을 만들어 볼 생각입니다.
